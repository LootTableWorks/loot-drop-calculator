Turn external RPG JSON into typed Godot 4 Resources

Parse external data as untrusted Variants, validate the wire contract, and convert records into project-owned Resources. Stable source IDs remain the join key; resource paths remain an implementation detail.

Before code

Keep the wire model separate from the game model

Godot's JSON parser returns Variants: dictionaries, arrays, strings, numbers, booleans, and null values. That flexibility is useful at the boundary but weak inside gameplay code. A production pipeline should have three explicit stages: parse JSON into Variants, validate and normalize the contract, then construct typed Resources or plain runtime objects.

Do not make source JSON carry Godot resource paths or script class names. A content record should identify an item as item.emberglass_vial, not res://items/emberglass_vial.tres. Stable IDs belong to the content domain and can survive a folder move. Resource paths belong to one Godot project and can be regenerated.

{
  "schemaVersion": 1,
  "items": [
    {
      "id": "item.emberglass_vial",
      "name": "Emberglass Vial",
      "baseValue": 48,
      "tags": ["alchemy", "fragile"]
    }
  ],
  "shopRows": [
    {
      "merchantId": "merchant.cold_lantern",
      "itemId": "item.emberglass_vial",
      "stockWeight": 18
    }
  ]
}
Pipeline rule

The parsed Dictionary is evidence from the wire. A typed Resource is the project-approved result of validation and conversion.

Step 1

Define narrow Resource types

Resources work well for immutable or mostly immutable definitions that several scenes and systems share. Give each definition its source ID and typed fields. Avoid embedding mutable inventory quantities, generated rolls, or per-save discoveries in the definition Resource.

class_name ItemDefinition
extends Resource

@export var source_id: StringName
@export var display_name: String
@export var base_value: int
@export var tags: Array[StringName] = []

func is_valid() -> bool:
    return not source_id.is_empty() \
        and not display_name.is_empty() \
        and base_value >= 0

StringName is useful for repeated identifiers inside the running project, but the wire value remains a string. Convert after checking that the input is a non-empty string. If a relationship needs additional edge data, model the edge as its own Resource or value object instead of maintaining parallel arrays.

class_name ShopStockRule
extends Resource

@export var merchant_id: StringName
@export var item_id: StringName
@export var stock_weight: int

# Resolved at catalog assembly time; never serialized from JSON.
var item: ItemDefinition

Keeping item_id after resolution helps save compatibility and diagnostics. The resolved item reference is a runtime convenience, not the identity.

Step 2

Validate Variants before constructing Resources

Use JSON.parse_string for a simple boundary or a JSON instance when you need parser error detail. Check the root type, schema version, collection types, required fields, and numeric ranges. JSON numbers arrive without your design semantics, so reject fractional values where the contract requires an integer.

static func parse_catalog(text: String) -> Dictionary:
    var root: Variant = JSON.parse_string(text)
    if typeof(root) != TYPE_DICTIONARY:
        push_error("Catalog root must be an object.")
        return {}
    if root.get("schemaVersion", -1) != 1:
        push_error("Unsupported catalog schema version.")
        return {}
    if typeof(root.get("items")) != TYPE_ARRAY:
        push_error("Catalog items must be an array.")
        return {}
    return root

Do not use as Dictionary or a typed variable as a substitute for validation. Verify each field before reading it. A helper that returns a result object with a list of issues is often better than stopping at the first problem because content authors can repair a complete batch in one pass.

static func item_from_row(row: Dictionary, path: String) -> ItemDefinition:
    var raw_id: Variant = row.get("id")
    if typeof(raw_id) != TYPE_STRING or raw_id.strip_edges().is_empty():
        push_error(path + ".id must be a non-empty string")
        return null
    if typeof(row.get("baseValue")) != TYPE_FLOAT:
        push_error(path + ".baseValue must be a JSON number")
        return null

    var item := ItemDefinition.new()
    item.source_id = StringName(raw_id)
    item.display_name = str(row.get("name", raw_id))
    item.base_value = int(row.baseValue)
    if float(item.base_value) != row.baseValue or not item.is_valid():
        push_error(path + " contains an invalid integer value")
        return null
    return item

When importing local user-selected data, enforce a byte cap before reading and parsing. Do not send the document to a network endpoint, analytics service, or error logger.

Step 3

Resolve relationships in a second pass

Create all item Resources and index them by source ID before processing any shop, recipe, quest, or loot relationship. Then validate each target against the completed dictionary. This supports forward references and makes source ordering irrelevant.

static func index_items(rows: Array) -> Dictionary:
    var by_id: Dictionary = {}
    for index in rows.size():
        var item := item_from_row(rows[index], "items[%d]" % index)
        if item == null:
            continue
        if by_id.has(item.source_id):
            push_error("Duplicate item ID: %s" % item.source_id)
            continue
        by_id[item.source_id] = item
    return by_id

static func resolve_stock(rule: ShopStockRule, items: Dictionary) -> bool:
    if not items.has(rule.item_id):
        push_error("Missing item %s for merchant %s" % [rule.item_id, rule.merchant_id])
        return false
    rule.item = items[rule.item_id] as ItemDefinition
    return true

Decide whether any validation error invalidates the catalog. For global definitions, all-or-nothing import is usually safer. If partial import is allowed for mod content, isolate it by package and make skipped records visible to the player or author. Silent skipping creates hard-to-reproduce gameplay gaps.

Step 4

Generate .tres files only when the workflow benefits

Runtime conversion is appropriate when content changes frequently, comes from approved mods, or does not need inspector references. Editor generation is appropriate when designers need native Resources, import errors should block export, or other assets need direct Resource references.

For editor generation, keep output in a dedicated generated directory, derive safe filenames from stable IDs, and call ResourceSaver.save only after the entire catalog validates. Maintain a manifest from source ID to generated path. On rebuild, update known IDs and remove generated files whose IDs are no longer present. Never delete outside the dedicated output directory.

@tool
static func save_item(item: ItemDefinition, output_dir: String) -> Error:
    var safe_name := String(item.source_id).replace(".", "_")
    if not safe_name.is_valid_filename():
        return ERR_INVALID_DATA
    var path := output_dir.path_join(safe_name + ".tres")
    return ResourceSaver.save(item, path)

Generated Resources should be treated like build artifacts. Either commit them under a clear generation policy or reproduce them during build preparation. Do not make them a second hand-edited source of truth.

Security boundary

Do not call load() or instantiate scripts from a path named in imported JSON. Map approved content IDs through project-owned code.

Preflight

Test parsing, conversion, and resolution separately

  • Malformed JSON and non-object roots fail cleanly.
  • Unsupported schema versions stop before Resource construction.
  • Missing, blank, and duplicate source IDs produce precise issues.
  • Fractional values are rejected for integer contract fields.
  • Forward references work after the complete item index exists.
  • Broken relationships report source and target IDs.
  • Reordering source arrays does not change resolved results.
  • Generated paths remain inside the dedicated output directory.
  • Two imports of the same source produce equivalent Resources.
  • Per-save state never leaks into definition Resources.
